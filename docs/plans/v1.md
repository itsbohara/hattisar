# hattisar v1 — implementation plan

**Spec:** [`docs/design.md`](../design.md) — binding. Section refs below (§n) point there.
Every task: read the spec sections it names before writing code.

## Global Constraints

- TypeScript (strict, ESM) on Node 24, **pnpm**. HTTP: **Hono** (`@hono/node-server`). SQLite:
  **better-sqlite3**. Postgres: **pg**. Docker: **dockerode**. S3: **@aws-sdk/client-s3** +
  **@aws-sdk/lib-storage**. Encryption to pg-meta: **crypto-js** (same as Studio). Tests:
  **vitest**; e2e **@playwright/test** (Chromium). Lint/format: **Biome**.
- Layout: `src/` (by feature: `studio/`, `registry/`, `auth/`, `boxes/`, `projects/`, `backups/`,
  `managed/`, `ui/`, plus `config.ts`, `app.ts`, `main.ts`), `sql/`, `docker/`, `test/unit/`,
  `test/integration/`, `e2e/`.
- Pinned images exactly as spec §12. hattisar always runs inside the compose network (§2).
- **No silent default DB** (§3 invariant) — any change touching the Studio proxy must keep it.
- SQL identifiers and literals are always escaped (`pg-format`-style `%I`/`%L`, or
  `pg`'s `escapeIdentifier`/`escapeLiteral`); never interpolate raw.
- Secrets never in logs, argv, error messages or HTML except the deliberate reveal on the
  project page.
- Comments: only traps, load-bearing negatives and non-local reasons. No narration.
- **Do not commit.** Leave changes in the working tree; the controller commits by layer.
- Do not dispatch subagents.
- Port note: a separate official Supabase stack may be running on the dev machine using 8000/54322/
  6543; the controller stops it before Task 1. If a port is still busy, report — don't change
  defaults.

Commands every task keeps working: `pnpm lint`, `pnpm typecheck`, `pnpm test` (unit),
`pnpm stack:up` / `pnpm stack:down`, `pnpm test:it` (integration, needs stack),
`pnpm test:e2e` (needs stack).

### Task 1: Foundation — tooling, lean stack, hattisar container

  official stack at
  `/private/tmp/claude-501/-Users-itsbohara-code-ideastorm/74252ecf-d4de-4106-b1e5-1a9536033a60/scratchpad/supabase/docker/docker-compose.yml`

### Task 2: Studio proxy core (spike)

Spec: §1, §3, §3.1, §3.2, §11.

Build in `src/studio/`:
- `crypto.ts` — `encryptConnectionString(conn, key)` with crypto-js AES (Studio-compatible).
- `connection.ts` — admin connection string for a project (URL-encoded user/password).
- `projects-source.ts` — interface `ProjectSource { list(user), get(user, ref) }` returning
  `{ref, name, boxName, dbName, box: {host, port, adminUser, adminPassword}}`. Spike
  implementation `SpikeProjectSource` reads `HATTISAR_SPIKE_PROJECTS` (JSON array) — removed in
  Task 7.
- `platform-routes.ts` — `/api/platform/projects` and `/api/platform/projects/:ref` per §3.1;
  `/api/ai/*` 404.
- `pg-meta.ts` — `POST /api/platform/pg-meta/:ref/query` per §3.2; other `/pg-meta/:ref/*` →
  strip + set header, pass through; unknown ref → 404. Debug log of resolved db per request and
  `/_hs/debug/pg-meta-log` (last 200, only when `HATTISAR_DEBUG=true`), per §13.
- `proxy.ts` — streaming pass-through to `STUDIO_URL`; redirects from §3 table; HTML injection
  hook (no-op stylesheet/script files for now; real content in Task 9).
- No auth yet (Task 5 adds it in front).

Tests: unit — crypto output decrypts with crypto-js to the input and has OpenSSL `Salted__`
prefix; route classification for every row of §3 table; header is stripped and replaced.
Integration — with two spike projects on the shared `db` (create `spike_a` with table `alpha`,
`spike_b` with table `beta` in a test setup via `docker compose exec db psql`): `GET
/api/platform/projects` lists both; `POST /api/platform/pg-meta/spike-b/query`
`select current_database()` → `spike_b`; `GET /api/platform/pg-meta/spike-b/tables` contains
`beta` and not `alpha`; unknown ref → 404; `/api/ai/sql/generate-v4` → 404.

Done when: unit + integration green; Studio UI loads at `/project/spike-b/editor` through hattisar.

### Task 3: Routing proof e2e — GO / NO-GO gate

Spec: §13 (routing test), §3 invariant.

Build `e2e/studio-screens.ts` (list of Studio paths for a ref: editor, sql/new, database/tables,
database/functions, database/triggers, database/extensions, database/roles,
database/policies (auth/policies if that's where Studio lists them), database/publications,
database/indexes, database/types, database/schemas, settings/general, advisors) and
`e2e/routing.spec.ts`: for project B visit each, wait for network idle, collect every
`/api/platform/pg-meta/**` request; then read `/_hs/debug/pg-meta-log` and assert every entry
in the window resolved to B's db; assert B's table `beta` is visible in the Table Editor and
`alpha` is not. Also assert no request in the window returned 5xx from pg-meta routes.

Report in the task report: the full list of pg-meta routes seen, any screen that errored, and a
clear **GO** or **NO-GO**. NO-GO = any request resolved to the wrong db or bypassed hattisar's
header. On NO-GO stop and report; do not work around it.

Done when: the spec passes (GO) or NO-GO is reported with evidence.
